# 验证、交付与复盘清单

宣布完成前，必须满足：

- 原始问题闭环已经通过；
- 回归测试或替代验证已经通过；
- known-good 路径没有被破坏；
- 无效修改、临时补丁、调试配置和一次性脚本已删除或回滚；
- 临时日志和探针已清理，或明确标记为调试用途；
- root cause、验证证据、修复方式、影响范围和剩余风险已经记录。

最终回复前，逐项检查：

- `[ ]` 原始问题闭环通过；
- `[ ]` 回归测试或替代验证通过；
- `[ ]` known-good 路径没有被破坏，或无法验证的原因已明确；
- `[ ]` 无效修改、临时补丁、调试配置和一次性脚本已删除或回滚，或保留原因已明确；
- `[ ]` 临时日志和探针已清理，或明确标记为调试用途；
- `[ ]` 未覆盖项和剩余风险已列出；
- `[ ]` 复盘已写。

交付结论包含：

- 问题现象；
- 影响范围；
- 根因；
- 修复方案；
- 验证方式；
- known-good 路径；
- 任何临时措施的撤销或替换说明；
- 未覆盖项；
- 剩余风险；
- 复盘。

复盘时回答：什么本可以防止这个 bug 出现？如果答案指向测试边界缺失、架构耦合、配置管理混乱、版本管理不清、日志不足或流程缺陷，把它作为后续改进项记录。不要在根因修复完成前借机大范围重构。
